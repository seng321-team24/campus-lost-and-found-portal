# M4 – Non-Functional Requirements: Ownership Claim and Verification

**Project:** Campus Lost and Found Portal
**Module owner:** Ceren Torun (@ccerentrn)

| ID | Quality attribute | Requirement | Target | Measurement method | Test |
|---|---|---|---|---|---|
| NFR-M4-01 | Privacy / access control | Claim and verification data is visible only to the claimant, the listing owner, and staff/admin. | 100% of unauthorized requests return 403 (401 if not signed in); 0 verification fields in those responses. | API response inspection | Automated API test with 4 roles (claimant, owner, other user, visitor) over all claim endpoints; at least 20 unauthorized requests. |
| NFR-M4-02 | Data integrity | A user cannot create a second claim on the same listing. | 0 duplicate claims in 50 attempts, including 10 parallel requests; API returns 409. | Integration test plus database query on a unique (item, claimant) pair | Integration test; manual database check. |
| NFR-M4-03 | Reliability | A submitted claim is never lost, and a failed submission leaves no partial record. | 100 of 100 submissions stored; 0 partial records after 10 injected failures. | Integration test with injected failure; row count comparison | Run in a test environment with a simulated database or network error. |
| NFR-M4-04 | Performance | Claim submission responds quickly under normal load. | p95 < 2 s at 20 concurrent users. | Load test | Load tool (e.g., k6 or JMeter) against the test environment. |

## Notes
- All targets are proposed. The team confirms them in the shared measurement table (`docs/nfr/00-main.md`).
- NFR-M4-01 supports FR-M4-07 and US-18. NFR-M4-02 supports FR-M4-04 and US-14.
- Personal data (name, e-mail, phone) is not exposed in claim lists to anyone outside the roles above (KVKK).
