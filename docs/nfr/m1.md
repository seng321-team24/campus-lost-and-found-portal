## 2. Requirement Specifications

### `NFR-M1-01`: Cryptographic Password Protection
* **Category:** Security
* **Description:** User passwords must never be logged, transmitted in unencrypted form, or stored in plain text anywhere within the application infrastructure.
* **Target Metric:** 100% of stored passwords must use `bcrypt` hashing with a minimum cost factor of 10 or `Argon2id`.
* **Test Procedure:** 
  1. Perform code review on user registration controller.
  2. Inspect database tables post-registration to confirm hash prefix (`$2a$`, `$2b$`, or `$argon2id$`).
  3. Verify logs to ensure password fields are masked.

### `NFR-M1-02`: Authentication Response Time
* **Category:** Performance
* **Description:** The system must process authentication requests rapidly to maintain seamless user experience during peak campus hours.
* **Target Metric:** $95\%$ of `POST /auth/login` requests must complete within $1000\text{ ms}$ ($p_{95} < 1.0\text{ s}$).
* **Test Procedure:**
  1. Execute automated load scenario using k6 with 50 virtual users.
  2. Measure round-trip time for `POST /auth/login`.
  3. Assert $p_{95}$ latency duration is less than $1000\text{ ms}$.

### `NFR-M1-03`: Personal Data Minimization (KVKK Privacy)
* **Category:** Data Privacy & Compliance
* **Description:** Public endpoints must strictly exclude user personal contact information (e.g., telephone number, personal email) to conform with university data protection guidelines.
* **Target Metric:** Zero personal user attributes exposed via public GET listings APIs.
* **Test Procedure:**
  1. Perform GET requests on item listings as an unauthenticated visitor.
  2. Validate payload fields against privacy rules schema.
  3. Ensure creator identity is limited to masked handles or anonymized system IDs.
